# Console verification checklist

ps5-browser builds, links and packages, and the shell has been exercised on the host with WebKitGTK ([screenshots](screenshots/README.md)). Nothing has run on a PS5 yet. This checklist is for the operator with a real console: run the steps in order, because each one depends on the previous. For every failure, capture what the step lists and stop; later steps are meaningless until it is fixed.

Background: [architecture.md](architecture.md) (what runs where), [ps5-runtime.md](ps5-runtime.md) (layout, environment, spawn contract).

## What to capture on any failure

- **UI log**: `/data/ps5browser/log.txt` (fetch it over FTP). It also lists the environment the UI set (`env FONTCONFIG_FILE=...` lines).
- **stdout/stderr of all three processes**: they go to the console's debug output. Read it with klogsrv (`nc PS5_IP 3232`) or etaHEN's klog (`nc PS5_IP 9081`), started **before** launching the browser. Spawner errors start with `ps5_spawn:`; elfldr-derived loader errors carry `elfldr.c:<line>`.
- **elfldr's own output** when sending the ELF with `nc` (keep the `nc` session open, without `-q0`, to see it).
- A photo or capture of the screen, the firmware version, the loader and HEN used (elfldr build, etaHEN version, kstuff), and the build commit (`git rev-parse HEAD`).

## 1. Prerequisites

1. A jailbroken PS5 with a kernel exploit and ps5-payload-dev/elfldr listening on port 9021. Public exploit paths cover firmware 1.00 to 13.60 (Relapse: 7.00 to 13.60; UMTX: 1.00 to 5.50; BD-J loaders up to 7.61); 14.00 and later have no public path as of 2026-10-30. See the firmware table in [research.md §2.2](research.md#22-firmware-coverage-as-of-2026-10-30). Note the exact firmware; the SDK's kernel offset table covers 1.00 to 14.10.
2. An FTP server on the console: ps5-payload-dev/ftpsrv (port 2121) or etaHEN's FTP (port 1337).
3. Optional: ps5-payload-dev/websrv (port 8080) for the launcher tile; klogsrv (port 3232) or etaHEN klog (port 9081) for debug output; shsrv (port 2323) for a shell.
4. Free space: about 175 MB in `/data`, plus room for the cache.
5. A DualSense paired with the console. Optional: a USB keyboard.
6. Network access from the console to the internet (DNS is IPv4 only in the SDK libc).

## 2. Install

From `dist/ps5browser/README-install.txt` (generated by `scripts/ps5/package.sh`):

1. Copy `dist/ps5browser/` to `/data/ps5browser/` and, for the tile, `dist/homebrew/ps5browser/` to `/data/homebrew/ps5browser/`, for example: `lftp -p 2121 PS5_IP -e "mirror -R dist/ps5browser /data/ps5browser; mirror -R dist/homebrew/ps5browser /data/homebrew/ps5browser; quit"`.
2. The browser must live in `/data/ps5browser/`: it re-launches `/data/ps5browser/ps5browser.elf` for its WebProcess and NetworkProcess (override with `PS5BROWSER_SELF_PATH`) and reads fonts, CA bundle and chrome from there.
3. Optional: copy `config.json.sample` to `config.json` and edit `home_url`, `language` (`en` or `ru`), `user_agent`.
4. Check the upload: `ps5browser.elf` must be exactly the size of the local file (about 162 MB). A truncated upload is the most likely cause of a load failure.

## 3. Launch

Start klog capture first, then one of:

- websrv: open `http://PS5_IP:8080/` and select the "ps5browser" tile.
- elfldr, loading the installed file: `echo file:/data/ps5browser/ps5browser.elf | nc -q0 PS5_IP 9021`.
- elfldr, over the network: `nc -q0 PS5_IP 9021 < dist/ps5browser/ps5browser.elf` (slower; the spawned processes still use the installed copy, so both must be the same build).

To quit, use Options → Quit; this also saves the session. Killing the process (PS button, closing from the loader) loses tabs and history changes since the last save.

## 5. Defects fixed on the host that need console confirmation

A console-readiness review found the defects below. They are fixed on the host (compile and unit tests only); each one can only be confirmed on hardware. The test that covers each is in brackets.

1. **Chrome event path** (h, g): chrome events (tab, navigation and menu buttons, address bar, OSK keys) were double-JSON-encoded and dropped by the shell. Confirm every chrome button reacts.
2. **Content paint offset** (d, f): the page was painted at y=0 under the chrome band while input was mapped 96 px lower. Confirm the page starts under the band and clicks land under the pointer.
3. **Chrome overlay and pointer** (b, f, g): the chrome view had an opaque background that blanked the page under the OSK and modal rects, and the pointer was not composited over the page. Confirm the page shows through around the chrome and the pointer is visible.
4. **Keyboard keysyms and text** (USB keyboard on a text field): DOM key codes were sent where WPE keysyms are expected, and text input was dropped. Confirm Enter, Backspace, arrows and typed characters in a page field.
5. **L2/R2 edges** (f, g): analog triggers fired their action on every frame while held. Confirm one page step per press, and that L2 in the OSK toggles Shift once.
6. **Wheel direction and magnitude** (f): a zero axis still scrolled one tick, every scroll was one line, and the vertical sign was probably inverted. Confirm direction, no horizontal drift, and that PageUp/PageDown scroll a page.
7. **Environment forwarding** (a, e): `FONTCONFIG_FILE`, `FONTCONFIG_PATH`, `PS5BROWSER_CA_BUNDLE`, `SYSTEM_LANGUAGE` must reach WebProcess and NetworkProcess. Confirm fonts render and HTTPS works (both are read only in the child processes).
8. **Spawn failure reporting** (c): a failed spawn left the page blank with no message in release builds. If spawning fails, confirm there is now a log line and WebKit's crash handling runs instead of a silent hang.
9. **OSK auto-open** (g): focusing a page text field did not open the OSK on the PS5. Confirm it opens by itself.
10. **Child reaping** (n): spawned processes were not reaped after kill or crash. Confirm that repeated WebProcess restarts (for example, closing and opening tabs for 10 minutes) do not exhaust processes.
11. **Chrome alpha blending and dirty rects** (b, g, n): semi-transparent chrome was copied opaque, closed overlays left ghosts, and idle pages were repainted every frame. Confirm clean redraw after closing the OSK or the menu.
12. **Unbounded media buffer** (j, n): progressive media without `Content-Length` or `Range` support could buffer the whole file in RAM. Confirm memory stays bounded during long playback.

Known unverified risks from the same review, worth watching while testing: a possible hang in the spawner's exec notification (UI freezes at the first spawn), fd 3 already being in use in the injected child, the UI keeping a 162 MB copy of its own ELF in memory, and per-player media memory with several videos on one page.
